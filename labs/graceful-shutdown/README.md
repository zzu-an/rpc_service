# 优雅退出

## 1. 解决什么问题？

收到 SIGTERM/SIGINT 后先停止接收新流量，给在途请求有限时间完成，再关闭数据库、MQ 等资源，避免滚动发布制造错误和半完成操作。

## 2. 错误写法会怎样？

直接退出会中断请求；只调用 `Shutdown` 却不设置超时可能永久等待；在 handler 完成前关闭数据库会让本可完成的在途请求失败。

## 3. 怎么检测？

- 集成测试取消进程 context，验证 server 返回且资源只在最后关闭。
- 发布时观察连接数、5xx、在途请求和 termination duration。
- 给 `/slow` 发请求后按 Ctrl-C，确认它能在退出窗口内完成。

## 4. 生产环境如何处理？

- 容器先 readiness 失败并等待流量摘除，再进入 shutdown。
- shutdown deadline 必须小于编排系统的 termination grace period。
- 消费者先停拉新消息，再提交/回滚在途消息。
- 超时后强制关闭并记录未完成工作；幂等、重试和补偿仍然不可少。
