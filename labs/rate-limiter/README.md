# 令牌桶限流

## 1. 解决什么问题？

把进入系统或下游的平均速率限制在可承受范围，同时允许不超过 `burst` 的短时突发。

## 2. 错误写法会怎样？

只用 `time.Ticker` 发令牌容易产生 goroutine 生命周期和 ticker 回收问题；不加锁的共享计数会数据竞争；只做全局限流会让一个热点用户吃掉全部额度。

## 3. 怎么检测？

- 使用可注入时间的确定性测试验证突发和补充速度。
- `go test -race ./labs/rate-limiter` 验证并发安全。
- 监控允许数、拒绝数、等待时间，并按路由/租户区分。

## 4. 生产环境如何处理？

- 网关、本机、用户/活动维度分层限流。
- 本机限流便宜但各实例不共享；Redis/Lua 可做分布式限流但会引入网络依赖。
- 先做容量评估，再配置 rate/burst；返回明确的 429 和 `Retry-After`。
- 秒杀还需库存资格校验、排队、熔断和负载保护，限流不是完整防线。
