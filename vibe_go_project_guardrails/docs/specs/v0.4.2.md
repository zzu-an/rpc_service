# v0.4.2 Redis Stream 秒杀热路径 Spec

## 目标

在独立分支中实现正式模式 `async-stream`，工作树不包含 Kafka 生产代码：

```text
HTTP → Redis Lua（资格、库存、buyer、XADD）→ 202
                                      ↓
                              Redis consumer group
                                      ↓
                              MySQL Purchase → XACK
```

它用于单独学习 Redis 原子入队、消费组和 PEL 恢复；Kafka 版本位于
`codex/v0.4.1-kafka`，两个方案通过 Git 切换而不是在同一进程中用配置切换。

## 非目标

- 不宣称 Redis Stream 与 MySQL 是 exactly-once；事务提交与 XACK 之间仍会重复处理。
- 不包含 Kafka、MySQL job 表、Outbox relay 或 Stream→Kafka Bridge。
- 不发布 OrderCreated 跨业务事件；相关学习在 Kafka 分支进行。
- 不做 Redis Cluster 客户端迁移、热点分桶、支付状态机、库存补偿或自动对账。
- 不引入 RPC、etcd、Prometheus、容器编排。

## 模式

- `sync`：v0.3 同步基线。
- `async-stream`：Redis Lua+XADD→MySQL，正式异步热路径；旧值 `async` 兼容到此模式。

`async-kafka` 在本分支启动时会被拒绝。需要 Kafka 方案时执行
`git switch codex/v0.4.1-kafka`，避免同一代码树同时展示两套恢复语义。

## Redis key 与 slot

同一 item 的所有 key 使用 `{item:<itemID>}`：

```text
seckill:v03:{item:42}:state
seckill:v03:{item:42}:buyers
seckill:v042:{item:42}:orders
seckill:v042:{item:42}:results
seckill:v042:{item:42}:retries
seckill:v042:{item:42}:dlq
```

Lua 的四个 key 同 slot，避免 Redis Cluster `CROSSSLOT`。不同 item 自然散列；单个 item
仍只能落在一个 shard，这是原子性与单热点横向扩展之间的明确取舍。

## 原子入队语义

Lua 顺序：检查 ready/活动窗口 → 先检查 buyer 重放 → 检查库存 → 减库存 → 保存 buyer →
写 QUEUED 结果索引 → `XADD` 版本化任务。首次成功返回 Stream ID；重放返回原 order_no，
不重复 `XADD`。任何脚本错误都不会留下“只减库存未入队”的局部结果。

order_no 使用自描述格式，包含毫秒时间和 itemID；查询接口从可信 order_no 解出 itemID，
再访问同 slot results。客户端不能额外提交 itemID 覆盖该结果。

## Stream 消费语义

- 每个 item 一个 Stream，同一 consumer group；worker 从 MySQL 周期发现启用中的 item。
- 新消息使用 `XREADGROUP ... >`；崩溃遗留 PEL 使用 `XAUTOCLAIM`。
- MySQL `Purchase` 成功后原子执行 `XACK + XDEL + 清 retry`。
- 临时错误保持 pending；达到最大次数或不可重试错误时，先 `XADD` 同 slot DLQ，再 ACK/删除源消息。
- worker 关闭时先停止发现和读取，再在有限预算内等待在途；未 ACK 消息由其他消费者认领。
- 全局 semaphore 限制 MySQL 并发；每 item 多消费者不代表可以超过数据库连接池预算。

## 结果查询

- 先按 userID+order_no 查询 MySQL；订单存在返回 `SUCCEEDED`。
- MySQL 不存在时读取 Redis results；所有者不匹配或不存在统一 404。
- DLQ 终态返回 `FAILED`，其他状态返回 `QUEUED`。
- Redis 结果 TTL 必须长于活动结束和允许积压窗口；不能与 state 的短缓存 TTL 相同。

## 可靠性边界

- Lua 原子只覆盖单 Redis shard，不能覆盖 MySQL。
- MySQL commit 成功、XACK 前宕机会重复消费；`orders.order_no` 和 claim 唯一索引兜底。
- Redis AOF/复制未落盘时整机故障仍可能丢任务；Stream 不是跨故障域的永久日志。
- `XACK` 只移出 PEL，不释放 Stream 内存，因此成功路径同时 `XDEL`。
- 不对主 Stream 使用无条件 MAXLEN 截断，避免积压消息仍在 PEL 时被删除。

## 配置

新增 `RedisStream`：consumer group、consumer 前缀、消费并发、批量大小、阻塞时间、
claim idle、发现周期、最大处理次数、任务保留期和关闭预算。所有值启动时校验为正数；
消费并发必须小于 MySQL 连接池上限。

## 验收标准

- [x] Redis Lua 并发 1000/库存 100：stock=0、buyers=100、Stream=100。
- [x] 同用户 100 并发：一个 order_no、一条 Stream 消息。
- [x] HTTP `async-stream` 经 Lua 原子入队后返回 202，仓库中不存在 job 表依赖。
- [x] Stream 重复处理 100 次只产生一笔订单和 claim。
- [x] PEL 可 reclaim；poison message 进入 DLQ 且后续消息不阻塞。
- [x] 结果查询严格校验 userID，并以 MySQL 订单事实优先。
- [x] 生产代码、配置、migration 和 Go 依赖中不包含 Kafka。
- [x] 关键代码有中文“为什么/失败边界/面试点”注释。
- [x] `make verify-v042`、race、vet、边界扫描和 `git diff --check` 通过。
