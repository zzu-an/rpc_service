# v0.4.2 阶段验收

## 一键门禁

```bash
make verify-v042 \
  TEST_DSN='<remote-test-dsn>' \
  TEST_REDIS_ADDR='192.168.0.107:6379' \
  TEST_REDIS_PASSWORD='<remote-test-password>' \
  TEST_REDIS_DB='<test-db>'
```

门禁不会打印 DSN 或 Redis 密码；测试数据使用随机业务标识和精确 ID 清理，不能指向生产依赖。

## 自动验证内容

1. 对全仓执行 race；Redis gate 真实并发验证库存、buyer、Stream 和 result 数量一致。
2. 真实 Redis Stream consumer group 把任务落到真实 MySQL，并把同一任务重复投递 100
   次，验证最终只有一笔订单和一条 claim。
3. 验证 PEL reclaim、不可重试消息进 DLQ，以及成功后 `XACK + XDEL`。
4. 扫描生产代码、配置、migration 与 `go.mod`，确保不存在 Kafka/job 残留。
5. 执行 `go vet`、里程碑边界扫描和 `git diff --check`。

## 通过条件

- Redis 库存不为负，成功准入数等于 buyer/主 Stream/result 数。
- MySQL 正式库存、claim 和订单数一致；重复投递不重复扣减。
- worker 关闭后没有遗留本轮主 Stream entry；临时 PEL 可由 `XAUTOCLAIM` 恢复。
- 不出现 Kafka、Kafka job migration、支付、补偿/对账生产 API。

## 仍然存在的边界

- Redis Lua 与 MySQL 不构成分布式事务；提交后、XACK 前崩溃依赖幂等重投。
- Redis 整机持久化/复制策略不由应用测试替代，AOF 与故障域必须在部署层配置。
- 单 item 同 slot 保证 Lua 原子性，也意味着它仍受一个 Redis shard 的吞吐上限约束。
- 本阶段证明正确性和链路缩短，不在没有同环境报告时宣称固定性能增益。
