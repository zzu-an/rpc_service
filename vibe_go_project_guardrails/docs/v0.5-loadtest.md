# v0.5 压测与容量说明

v0.5 不把“增加微服务/Kafka”宣传成吞吐提升。RPC 增加网络跳数，Outbox 增加本地写入；它们换来的是
所有权、故障隔离与可扩展下游，而不是免费性能。

本阶段固定验证的是正确性负载：库存 100 下 1000 并发不超卖、同用户或同任务 100 次不重复、Kafka
事件重复 100 次不重复创建通知/投影、4 个 orchestrator 并发不突破配置上限。每次正式容量测试仍应记录：

- gateway 接受/拒绝/timeout 与 P50/P95/P99；
- Redis 接受数、Stream 长度与 PEL；
- inventory reservation、order、Outbox backlog 和 `reserved_without_order`；
- Kafka 两个 group 的独立 lag、retry、DLQ；
- RPC 每依赖 attempt、deadline、breaker open 与 goroutine/连接池峰值。

扩 order-rpc 前必须核对 MySQL `MaxOpenConns × 实例数`；扩 notification consumer 前必须保证 topic partition
不少于有效 consumer 数。实例增加但 partition/数据库预算不变时，吞吐不会线性提升，反而可能放大重试和连接竞争。
