# v0.1 单体商城：运行与验收

本文是 `vibe_go_project_guardrails/docs/specs/v0.1.md` 的执行记录。v0.1 解决的是单体应用中的基础业务正确性：REST 接口组织、MySQL 持久化、JWT、实时 RBAC、商品资料与不含库存的订单本地事务。

## 本地环境

- API：`127.0.0.1:8888`
- MySQL Docker 容器：`service-rpc-mysql`
- MySQL 映射端口：`127.0.0.1:3307`
- 开发数据库：`service_rpc`
- 隔离测试数据库：`service_rpc_test`

本项目刻意不提供 Docker Compose。首次创建 MySQL 时可使用 MySQL 8 单容器，并把数据保存到命名 volume；数据库密码应由本地环境提供，不要复用于生产环境。

## 启动

确认 MySQL 容器健康后，应用 migration 并启动 API：

```bash
make migrate-up
go run . -f etc/store-api.yaml
curl http://127.0.0.1:8888/healthz
```

`GET /healthz` 只表示进程能够接收请求，不代表所有下游均健康。

## 阶段质量门禁

先为 `service_rpc_test` 应用 `migrations/` 下的全部 SQL，再显式传入测试 DSN：

```bash
make verify-v01 \
  TEST_DSN='service_rpc:service_rpc_dev@tcp(127.0.0.1:3307)/service_rpc_test?charset=utf8mb4&parseTime=true&loc=UTC'
```

`verify-v01` 在没有 `TEST_DSN` 时主动失败，避免 MySQL 集成测试被跳过却产生误导性的绿色结果。该入口执行完整 race 测试和 `go vet`；普通快速测试可使用 `make test`。

## 已验收业务链路

1. 注册与重复邮箱冲突。
2. 密码登录、JWT 签发、当前用户查询，以及缺失、篡改、过期 Token 拒绝。
3. 普通用户访问管理接口返回 403；管理员依据 MySQL 最新 RBAC 结果授权并替换用户角色。
4. 商品创建、更新、上下架、公开分页列表与详情；公开查询不会暴露下架商品。
5. 登录用户创建订单；金额由服务端按 SKU 当前价格计算并保存快照，订单头与明细同一事务提交或回滚。
6. 订单只能由所属用户读取；不存在与越权统一返回 `ORDER_NOT_FOUND`。

## 阶段边界与下一问题

商城业务代码没有 Redis、MQ、RPC、etcd、分布式锁或库存读写。v0.1 因此只证明基础业务和本地事务正确，不证明并发库存正确性。

下一阶段 v0.2 要回答：高并发下仅使用 Go 与 MySQL 时，如何保证库存不为负、成功订单数不超过库存，并让重复请求不会重复扣减。开始 v0.2 前必须先创建并批准对应 TASK，不能从路线图直接扩展实现。

## 2026-08-22 验收结果

v0.1 已通过最终门禁：

- 隔离测试库从空库应用到 migration `version=5 dirty=false`，重复执行为 `no change`，并通过 `5 -> 4 -> 5` 单步回退与恢复。
- `make verify-v01 TEST_DSN=...` 的全量 MySQL 集成测试、race detector 与 `go vet` 全部通过。
- 真实端口主链路通过；订单验收中伪造总额 `1` 被忽略，服务端按单价 `1999`、数量 `2` 计算为 `3998`，其他用户读取返回 404 `ORDER_NOT_FOUND`。
- 最终代码扫描未发现 Redis、MQ、RPC、etcd、分布式锁或库存实现；仅保留解释“为何无库存”的边界注释。

详细逐任务证据见 `vibe_go_project_guardrails/docs/tasks/`，其中 TASK-001 至 TASK-009 均已完成。


## 文件结构

核心架构（自上而下）
```text
main.go                          ← 程序入口，组装所有模块
│
├── etc/store-api.yaml         ← 配置文件（端口、MySQL连接、JWT密钥）
├── internal/config/config.go  ← 配置结构体定义
│
├── internal/platform/database ← 基础设施层：MySQL 连接管理
│
├── internal/handler/          ← HTTP 路由层（最外层）
│     ├── register.go          ← 注册路由的总入口
│     ├── login.go             ← POST /v1/auth/login, GET /v1/users/me
│     ├── rbac.go              ← 权限管理路由
│     ├── product.go           ← 商品路由
│     └── order.go             ← 订单路由
│
├── internal/user/             ← 用户领域（注册、认证）
│     ├── user.go              ← 领域模型 + Service（注册逻辑）
│     ├── auth.go              ← 认证逻辑（密码校验）
│     └── mysqlrepo/           ← 用户的 MySQL 仓储实现
│
├── internal/auth/             ← JWT Token 管理（签发、解析、过期）
├── internal/rbac/             ← RBAC 权限控制（角色、权限分配）
├── internal/product/          ← 商品领域
├── internal/order/            ← 订单领域
│
├── migrations/                ← 数据库迁移文件（建表 SQL）
└── cmd/migrate/main.go        ← 数据库迁移命令行工具

```
